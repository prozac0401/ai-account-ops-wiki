## 다운로드와 실행을 분리한다

C19는 Drive에서 ZIP을 받아 푼 EXE와 직접 받은 EXE의 다운로드 표시·`Zone.Identifier` 상태가 달랐다는 특정 파일 관찰이다. ZIP 경로가 일반적으로 안전하거나 모든 경고를 제거한다는 근거가 아니다. 브라우저의 Keep 선택, 다운로드 완료, 서명 표시, 실행 성공, 현장 검수는 각각 다른 증거다.

Microsoft의 `Unblock-File`은 파일의 인터넷 출처 표시를 제거하는 기능이지 파일을 신뢰할 수 있게 만드는 검사 기능이 아니다. 출처·내용을 먼저 확인하라는 공식 주의를 따른다. 일괄 차단 해제나 SmartScreen 비활성화를 표준 절차로 두지 않는다. [공식 확인: 2026-09-07(P20)](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/unblock-file?view=powershell-7.5)

## 배포 게이트

다음은 조직 채택 전 제안이다.

| 단계 | 확인할 증거 | 판정 |
|---|---|---|
| 원본 선정 | 배포 책임자, 릴리스 버전, 원본 위치·시각 | 출처 불명은 HOLD |
| 파일 대조 | 원본과 수신본 SHA-256, ZIP·내부 EXE 각각의 식별 | 불일치는 중단 |
| 서명 확인 | 서명자, 인증서 신뢰, 타임스탬프, 검사 결과 | self-signed·서명 유효 표시만으로 조직 승인 대체 불가 |
| 단일 PC 검증 | 실제 OS·사용자 권한·보안 경고, 기능·삭제 범위 | 실패 원인과 복구 확인 |
| 현장 검증 | 도구별 체크리스트와 독립 종료 확인 | 버전별 합격 필요 |
| 확대·인계 | 승인된 대상 PC 수, 성공·실패·보류, 인수자 확인 | 다운로드 수로 실행 성공 수 대체 금지 |

예외 실행 승인은 보안 담당자와 배포 책임자가 파일 단위로 기록한다. 최신본이라는 이름만으로 덮어쓰거나 이전 도구의 검수 결과를 재사용하지 않는다. 이번 보완에서는 파일 배포·설치·차단 해제를 수행하지 않았다.

## 네트워크 배포 후보

48대 PC 환경에서 Windows 공유의 20연결 제한이 논의되었고 MQTT·UDP 방식이 제안되었다(C12). 실제 채택·배포 성공은 확인되지 않았다(U12). 수신 인증, 중복 실행 방지, ACK·실패 로그, 재전송, 방화벽, 버전 검증을 결정하기 전에는 현장 표준으로 기록하지 않는다. 이 문서는 새로운 네트워크 도구 구현이나 제한 우회를 지시하지 않는다.
