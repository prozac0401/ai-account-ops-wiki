## 범위와 상태

Google Workspace 구독 결제와 계정별 Colab PAYG(Pay As You Go) 구매를 분리한다. Business·Organization 결제 프로필의 사용자 초대는 공식 기능이다. 지원이 안내한 공유 프로필 구매 흐름은 **원본 자료 확인: F17–F18 검토 기록 기준**이다. 원본 EML을 이번에 직접 재검증한 것은 아니다.

49계정(00–48)을 같은 결제 프로필로 운영하려는 요구가 있었지만, 전 계정 구매·CU 반영·권한 회수 성공 증거는 없다(U10). 아래 단계·역할·완료 기준은 **조직 채택 전 설계·제안**이다. 지원 안내와 전체 도입 성공을 구분한다.

## 사전 준비

| 확인 항목 | 통과 기준 |
|---|---|
| 대상 | 계정 별칭, 과정, 구매 상품·수량·통화, 승인 예산이 일치 |
| 프로필 | 개인용이 아닌 Business·Organization 유형과 결제 담당자 확인 |
| 권한 | 초대자는 Admin 또는 사용자 관리 권한 보유, 자신의 권한을 넘겨 부여하지 않음 |
| 서비스 | 대상 OU의 Google Pay 서비스 허용 상태와 Colab 서비스 접근 확인 |
| 증빙 | 원본 영수증·구매 화면을 보관할 제한된 내부 위치 지정 |

F17의 `OR-AC-01`은 지원이 Google Pay 서비스·OU 설정을 점검하도록 안내한 사례다. 모든 구매 오류가 같은 원인이라고 단정하지 않는다. 오류 코드, 대상 OU, 서비스 상태를 기록하고 반복 구매 전에 원인을 확인한다.

## 초대와 구매

1. 결제 담당자가 Payments Center의 대상 프로필에서 `Settings → Payments users → Manage payments users`를 연다. 대상 계정의 미초대·대기·활성 상태를 먼저 확인하여 중복 초대를 피한다.
2. 계정별 구매에 필요한 `Sign-up and purchase` 권한을 최소 범위로 초대한다. 결제 프로필 정보가 여러 연결 상품에 노출될 수 있음을 확인한다.
3. 대상 계정으로 초대를 수락한다. 공식 안내상 초대는 2주 뒤 만료되므로 발송과 수락을 별도 기록한다.
4. Colab과 결제 화면의 **실제 로그인 계정**, 선택된 프로필, PAYG 상품, 결제 금액을 사람이 확인한다. 프로필 전환이 모든 상품에서 지원된다고 가정하지 않는다.
5. 승인된 구매를 계정별로 수행하고 영수증·주문 결과·구매 전후 CU를 확보한다. 버튼 클릭 또는 결제 화면 도달만으로 구매 성공 처리하지 않는다.
6. 오류·중복 결제 의심 시 재구매하지 않고 결제 담당자가 거래를 대조한다. 1계정 검증 후 3 → 10 → 전체 확대 여부를 별도 승인한다.

초대 권한·만료·프로필 제약의 공식 확인일은 2026-09-07이다. [결제 프로필 사용자 관리(P08)](https://support.google.com/paymentscenter/answer/7162853?hl=en)

## 증빙과 권한 회수

1. 구매 계정별 영수증과 CU 증가를 대조하고 수집 상태를 [[services/Colab_CU와_런타임_운영|CU 대장]]에 기록한다.
2. 구매자 계정의 영수증 수신·조회와 관리자 쪽 접근을 따로 확인한다. 공유 프로필이면 모든 영수증을 관리자가 계속 볼 수 있다고 가정하지 않는다.
3. 대상 계정이 primary contact라면 다른 담당자로 먼저 변경한다. 결제 담당자가 임시 구매 권한 또는 프로필 사용자를 회수하고 재조회한다.
4. 회수 후 CU 잔량, 기존 영수증 접근, 추가 구매 가능 여부를 각각 확인한다. 아직 결과가 없으면 완료 대신 HOLD와 U05를 남긴다.

기존 CU 유지와 라이선스·프로필 회수의 관계는 서로 다른 질문이다(U04·U05). 권한을 무기한 남겨 문제를 피하지 말고, 미확인 위험과 다음 확인 담당자를 승인·인계 기록에 남긴다.

## 과거 방식과의 차이

F08의 계정별 카드 입력 도구에는 DPAPI CurrentUser 저장 설계가 있었고 CVV 파일 저장과는 구분되었다. 암호화 저장이 있어도 공개 가능한 데이터는 아니다. F07의 Colab Manager 방향은 공유 프로필 초대·계정별 구매·CU·증빙 관리이며, 모든 계정에 카드를 저장하는 방식을 현재 표준으로 삼지 않는다.
