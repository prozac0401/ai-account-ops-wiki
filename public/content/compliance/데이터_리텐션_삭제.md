## 개요

AI 서비스에서 “사용자를 제거했다”와 “데이터를 삭제했다”는 같은 말이 아니다.

이 문서는 교육 종료 후 어떤 데이터가 남을 수 있는지, 무엇을 삭제할 수 있는지, 무엇을 사용자가 직접 해야 하는지 정리한다.

## 리텐션이란

리텐션(retention)은 데이터를 얼마 동안 보관하는지를 뜻한다.

쉬운 말로는 “언제까지 남아 있나”다.

## ChatGPT Business / OpenAI

### 대화 삭제

OpenAI 도움말은 채팅을 삭제하면 계정 화면에서 즉시 제거되고, OpenAI 시스템에서 30일 내 영구 삭제 예정이라고 설명한다. 다만 이미 비식별화되었거나, 보안 또는 법적 의무로 더 오래 보관해야 하는 경우는 예외다.

보관(archive)은 삭제가 아니다. Library가 제공되는 계정·워크스페이스에서 **채팅 삭제와 Library 파일 삭제는 별도**다. GPT·프로젝트 첨부는 해당 GPT·프로젝트를 삭제할 때까지 보관되며, 삭제 뒤 30일 내 제거에 법적·보안 예외가 적용된다. [채팅·파일 정책(P36)](https://help.openai.com/en/articles/8983778-chat-and-file-retention-policies-in-chatgpt)

### 계정 삭제

OpenAI 계정 삭제는 영구적이고 되돌릴 수 없다. 계정 삭제 시 데이터는 30일 내 삭제된다고 안내된다. 단, 법에서 요구하거나 허용하는 일부 데이터는 더 오래 보관될 수 있다.

Business·Enterprise·Edu 등 관리형 워크스페이스에는 셀프서비스 계정 삭제가 제공되지 않으므로 조직 담당자에게 요청한다. 개인 계정의 삭제 경로를 관리형 계정에 그대로 안내하지 않는다. 계정 삭제는 ChatGPT뿐 아니라 같은 계정의 API 접근에도 영향을 주며, 모바일 스토어 구독은 별도 취소 여부를 확인한다. [계정 삭제 범위(P49)](https://help.openai.com/en/articles/6378407-how-to-delete-your-account)

### API 저장 데이터

API의 학습 제외와 무보존은 같은 말이 아니다. 기본 abuse monitoring 로그는 최대 30일 보관하며 법률·위해 방지 예외가 있다. 애플리케이션 상태는 엔드포인트별로 다르다. [API 데이터 제어(P40)](https://developers.openai.com/api/docs/guides/your-data)

| 데이터 | 확인할 수명·종료 조치 |
|---|---|
| Responses | 기본 또는 `store=true`의 상태 보존은 30일 기준이며 최소 30일 저장 안내. `store=false`를 전체 로그 무보존으로 해석하지 않음 |
| Conversations·항목 | 삭제할 때까지 보관되는 리소스. 종료 시 별도 삭제 확인 |
| Files·Vector Stores | 파일 삭제·만료 설정과 저장소 삭제를 별도 확인 |
| 승인된 ZDR·MAM | 조직·프로젝트 설정, 지원 엔드포인트·모델·안전 검토 예외 확인 |
| 외부 MCP·연결 서비스 | 해당 서비스의 저장·삭제 정책도 확인 |

이 표는 [엔드포인트별 보존표(P40)](https://developers.openai.com/api/docs/guides/your-data)의 운영 요약이다. 키 폐기와 프로젝트 보관은 데이터 삭제 증거가 아니다. 삭제 대상·요청 시각·확인 결과를 [[templates/계정_운영_기록|운영 기록]]에 남긴다.

### 운영상 주의

- 워크스페이스에서 멤버를 제거해도 계정 자체가 삭제되는 것은 아니다.
- 수강생 개인 계정의 삭제는 사용자가 직접 해야 할 수 있다.
- 조직은 “서비스 접근 회수”와 “데이터 삭제 요청”을 구분해서 안내해야 한다.

## Cursor

Cursor의 계정 삭제 도움말은 활성 구독 취소 후 대시보드에서 계정을 삭제하도록 안내하며 계정·관련 데이터의 30일 내 제거를 설명한다. **로컬 프로젝트 파일과 작성한 코드는 남는다.** 삭제 권한과 승인을 확인하고 PC 초기화까지 자동 완료됐다고 보고하지 않는다. [계정 삭제(P35)](https://cursor.com/help/account-and-billing/delete-account)

Privacy Mode는 학습 사용을 막는 통제다. Enterprise 기본 ON, Teams·Enterprise 조직 강제 설정, 새 멤버의 팀 설정 상속을 구분한다. BYOK·별도 보존 모델·정책 위반 조사에는 무보존 예외가 있으므로 [[services/Cursor|Cursor의 적용 범위]]를 함께 확인한다. [Privacy 설정(P32)](https://cursor.com/help/security-and-privacy/privacy), [데이터 사용·예외(P34)](https://cursor.com/data-use)

### 운영상 주의

- 팀에서 멤버를 제거하는 것과 사용자가 계정을 삭제하는 것은 다르다.
- 코드베이스 인덱싱 데이터가 있을 수 있으므로 계정 삭제 또는 인덱싱 설정을 별도로 봐야 한다.
- `.cursorignore`와 실습용 레포 사용이 중요하다.

## Claude Team / Enterprise

Anthropic 문서에 따르면 조직에서 사용자가 제거되면 남은 멤버는 그 사용자의 chats에 접근할 수 없다. 하지만 제거된 사용자의 데이터는 조직 Primary Owner의 data export에 포함될 수 있다고 안내된다.

또한 Anthropic의 조직 데이터 보존 문서는 API 입력·출력이 기본적으로 30일 내 백엔드에서 삭제된다고 설명하지만, 법적 준수, 사용 정책 집행, 별도 합의 등 예외가 있다.

2026-09-07에도 Enterprise custom retention의 최소 기간은 30일로 확인했다. 기본은 기간 미설정 시 계속 보관이며, 기간을 줄여 저장하면 새 기준을 지난 데이터가 즉시 삭제된다. Primary Owner·Owner는 자료 인계와 승인 없이 기간을 줄이지 않는다. [Enterprise 보존 설정(P46)](https://support.claude.com/en/articles/10440198-configure-custom-data-retention-controls-for-enterprise-plans)

이용 정책 위반으로 플래그된 입력·출력은 최대 2년, 분류 점수는 최대 7년 보관될 수 있고 Covered Models에는 별도 안전 검토 보존이 적용된다. 일반 30일 설명만으로 예외 없는 삭제를 약속하지 않는다. [조직 데이터 정책(P44)](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data)

## Google Workspace / Colab

Google Workspace에서는 사용자 계정, 라이선스, 서비스 데이터가 분리된다.

- 라이선스 회수: 유료 기능 사용권 제거
- 계정 정지: 로그인 제한
- 계정 삭제: 사용자 계정 삭제
- 데이터 이전/보관: Drive, Gmail 등 데이터 처리
- Colab 라이선스 회수: Colab Pro/Pro+ 기능 제거

Colab 교육 후에는 라이선스 회수와 서비스 접근 권한을 확인한다. 노트북 파일이 Drive에 저장되어 있다면 Drive 데이터 정책도 함께 봐야 한다.

Google 계정을 정지해도 데이터는 삭제되지 않으며 공유 문서 공동작업자의 접근과 과금은 남을 수 있다. [[services/Google_Workspace_및_Colab|계정 정지·세션 회수]]와 계약별 청구를 확인한다. Colab 기존 CU의 라이선스·결제 프로필 회수 후 효과는 U04·U05의 미확인 사항이며 삭제·유지 어느 쪽도 확정하지 않는다. [정지 영향(P42)](https://knowledge.workspace.google.com/admin/users/suspend-a-user-temporarily)

```text
교육 종료 후 서비스 접근 권한은 운영자가 회수합니다.
다만 사용자의 개인 계정 자체 삭제나 개인 대화 삭제는 서비스별 정책에 따라 사용자가 직접 진행해야 할 수 있습니다.
삭제를 원하는 경우 교육 담당자에게 문의해 주시면 서비스별 절차를 안내드립니다.
```

## 자주 헷갈리는 점

### 멤버 제거와 삭제는 왜 다른가?

멤버 제거는 접근권을 끊는 것이다. 삭제는 데이터 자체를 없애는 것이다. 서비스는 보통 이 둘을 따로 처리한다.

### 30일이면 무조건 모두 삭제되는가?

아니다. 보안, 법적 의무, 비식별화, 사용 정책 집행 같은 예외가 있을 수 있다.

### 수강생에게 “다 삭제됩니다”라고 안내해도 되나?

권장하지 않는다. “서비스별 정책에 따라 삭제 또는 보관될 수 있다”고 안내한다.
