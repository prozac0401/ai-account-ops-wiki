## 문서 책임과 갱신

이 위키는 공식 담당자의 업무에 쓸 매뉴얼과 운영 백서를 목표로 한다. 문서가 있다는 사실이 조직의 공식 승인 완료를 뜻하지 않는다. 아래 책임·주기는 채택 제안이다.

| 문서 영역 | 검토 책임 역할 | 갱신 계기 |
|---|---|---|
| 계정·초기화·자동화 | 계정 관리자 | 과정 시작 전, 도구 버전 변경, 회수 후 |
| 구매·정산·정책 가격 | 결제 담당자 | 구매 직전, 정책 변경, 갱신·인보이스 확인 후 |
| 개인정보·보안 | 보안·개인정보 담당자 | 새 데이터·외부 연결·사고·계약 변경 |
| 교육·인수인계 | 교육 담당자 | 과정 전후, 담당자 변경 |
| 사건 백서 | 사건별 최종 책임자 | 새 증거 확보·복구·종료 승인 시 |

각 변경에 검토일, 변경 이유, 근거 ID·URL, 적용 범위, 승인 상태, 미확인 U번호를 남긴다. 화면의 공통 "검토용" 표시는 모든 정책이나 사건의 동일 상태를 뜻하지 않으므로 본문의 상태를 함께 읽는다.

## 배포·접근 제한의 확인 범위

현재 저장소에는 main push 시 빌드하고 gh-pages로 게시하는 GitHub Actions 정의가 있다. **설정 파일 존재는 최근 실행 성공이나 현재 서비스와의 연결 증거가 아니다.** C23의 Azure Free 운영 기억과 조사한 main의 관계는 확인되지 않았다(U01). 실제 배포 URL·호스팅·소스 브랜치·커밋·실행 기록·접근 규칙이 필요하다.

Azure Static Web Apps를 사용한다면 `authenticated`는 조직 구성원 확인과 같지 않다. 허용 역할·테넌트 조건을 실제 설정에서 검증한다. 클라이언트의 hash 경로·메뉴 숨김만으로 접근을 통제하지 않는다. Markdown 원본(`/content/…`), 첨부 파일, fallback 경로에도 서버 측 허용 규칙이 적용되는지 확인한다. 공개 GitHub 원본은 사이트 로그인과 별개로 접근할 수 있다. [인증(P18)](https://learn.microsoft.com/en-us/azure/static-web-apps/authentication-authorization), [경로 설정(P19)](https://learn.microsoft.com/en-us/azure/static-web-apps/configuration), 확인일 2026-09-07.

## 편집과 검증

1. 현재 지침과 STYLE_GUIDE를 읽고 기존 수정·최신 main과 차이를 확인한다.
2. [[SOURCES|다섯 근거 등급]]을 표시하고 정책·가격을 공식 원문에서 다시 읽는다.
3. 새 Markdown은 `src/main.js`의 docs·sections에 등록하고 Home·PAGE_TREE·_Sidebar 및 관련 서비스 링크를 연결한다.
4. 내부 링크는 등록 ID와 정확히 맞춘다. 현재 렌더러는 `.md` 제거와 등록 파일 stem 조회를 지원하지만 `../` 경로를 정규화하지 않는다. 기존 `../Home`은 정확한 `Home`으로 고친다.
5. `npm run build`, 등록 파일·링크 검사, 검색·목차·대표 페이지의 표·양식을 확인한다.
6. 민감정보·사건 날짜·금액·제안 상태를 검토하고 실제 수행한 검증만 기록한다. 게시 승인은 별도이며 이번 작업 범위가 아니다.
